# 容器与云原生基础

## 一、容器不是虚拟机：三件套推演

| 机制 | 管什么 | 一句话原理 |
|------|--------|-----------|
| namespace | **看得见什么**(视图隔离) | pid/mnt/net/uts/ipc/user 各自成轴，clone(flag) 时创建 |
| cgroup | **能用多少**(资源配额) | cpu/memory/io/pid 挂树限流；OOM kill 按 memory 层打分 |
| unionfs(overlay2) | **文件从哪来** | lowerdir(镜像只读层) + upperdir(容器可写层) 联合挂载，写时复制 |

- `docker run` 的内核事实 = 一个带全套 namespace 标志的 clone() + cgroup 归组 + pivot_root 切根 —— **没有 guest kernel**（对比 VM 的 hypervisor+独立内核），所以启动 ms 级、密度千级/机
- 进入容器即 `nsenter` 进目标 namespace 集——"ssh 进虚拟机"的心智是错的

## 二、镜像分层工程学

```dockerfile
# 分层缓存: 变化少的在前, 依赖安装单独成层(代码改动不触发重装)
COPY go.mod go.sum ./
RUN go mod download          # ← 依赖层(稳定)
COPY . .
RUN CGO_ENABLED=0 go build -ldflags="-s -w" -o app .   # ← 静态编译见下
FROM gcr.io/distroless/static   # 多阶段: 构建环境不进最终镜像
```

- 层内容寻址(SHA256)→相同层跨镜像共享存储与传输；`docker history` 逐层审计体积
- **多阶段构建 + distroless/scratch** 是安全与体积双优解；glibc 动态二进制换 alpine(musl) 有 DNS 兼容税（[[LibC与动态链接]] §一 nsswitch 差异）
- `.dockerignore` 防 secrets/构建产物入层——**层即使后删也留在历史里**，密码写进早期层再 RM 无效

## 三、K8s：声明式 API 与控制循环

```
期望状态(yaml) ──提交──▶ etcd ──watch──▶ 控制器(Reconcile 循环: 观测diff→行动收敛)
调度器: 过滤(资源/亲和性/taint容忍) → 打分(均衡度/镜像局部性) → 绑定节点
kubelet: CRI 拉镜像建容器 → 探针(liveness 重启 / readiness 摘流量 / startup 缓启动)
```

- 心智转变：命令式("帮我起个容器") → 声明式("集群应长这样"，控制器永续收敛)——自愈/滚动更新/水平扩缩全是同一循环的不同表现
- Service/Ingress 流量路径：ClusterIP(iptables/IPVS 规则随机选后端) → Ingress(L7 路由)；DNS 名 `<svc>.<ns>.svc.cluster.local`
- 配置注入两通道：ConfigMap(env/volume)+Secret(base64 非加密!需 RBAC+etcd 加密配合)

## 四、资源管理与排障速查

| 症状 | 根因域 | 动作 |
|------|--------|------|
| Pod 反复重启 | liveness 误杀/应用 OOM | `describe` 看 exit code: 137=cgroup OOMKill → 提 limit 或查泄漏([[LibC运行时排查-TLS与锁]] §四) |
| CPU throttling 毛刺 | limit 限流周期内耗尽 | 降低 limit 或放宽; P99 尾延迟元凶之一 |
| CrashLoopBackOff | 启动即退 | logs --previous; readiness/liveness 起始延迟不足 |
| ImagePullBackOff | 凭证/网络 | imagePullSecrets; 私仓连通 |
| 服务不通 | 网络/标签选择器 | endpoints 是否有 IP → NetworkPolicy → kube-proxy 模式 |

资源模型：requests(调度依据) vs limits(运行上限)——**Guaranteed(requests==limits)** 给延迟敏感负载；超卖比是容量规划核心参数。
