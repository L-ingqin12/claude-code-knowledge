# 计算机组成原理

> [!abstract] 定位
> 硬件层机制级拆解：数制表示、流水线与乱序执行、存储层次与缓存一致性、虚拟内存硬件侧、SIMD 向量化、IO 路径，以及**性能方法论**（为什么你的代码慢——从硬件找根因）。每节挂工程锚点；软件侧对接 [[操作系统八股]]。

See also: [[CS-KB-Home]] · [[操作系统八股]] · [[数据库原理与调优]] · [[CPP-核心知识]]

## 一、数的表示（一切 bug 的源头之一）

| 主题 | 要点 |
|------|------|
| 补码 | `~x+1`；无 ±0；有符号溢出在 C/C++ 是 **UB**（编译器据此做消除分支等激进优化） |
| IEEE754 float | 1 符号 +8 指数 +23 尾数（隐含 1）；double 11/52 |
| 精度陷阱 | `0.1+0.2≠0.3`（二进制无限循环）；比较用 epsilon；金额用整数分/decimal |
| 特殊值 | inf/NaN（NaN≠NaN）；subnormal 填充下溢梯度（部分硬件降速） |
| 溢出检查 | `-ftrapv`/内建 `__builtin_add_overflow` 族 |

## 二、指令集与流水线

- **ISA**：x86-64 变长指令(CISC 外壳)/ARM64 定长(RISC 内核)；微操作(μop) 让两者在后端趋同
- 五级经典流水线 IF→ID→EX→MEM→WB；理想 IPC=1，超标量多发射后 IPC>1

### 三类冒险与解法
| 冒险 | 场景 | 硬件对策 | 软件配合 |
|------|------|---------|---------|
| 结构 | 功能部件争用 | 资源复制 | — |
| 数据 RAW | 后指令用前结果 | **前递(forwarding)** EX/MEM→EX | 减少紧邻依赖链 |
| 控制 | 分支去向未知 | 分支预测+投机执行 | 可预测分支布局(`[[likely]]`) |

- load-use 固定延迟：即使前递也要空一拍 → 数组遍历中"先读后算相邻两元素"会串行化
- **分支预测**：2bit 饱和计数器→两级自适应→BTB 目标缓存→TAGE 类历史匹配；误预测代价 ≈15–20 cycle（现代深流水）。排序前预处理数据让 if 更可预测是真实优化（CSAPP/论文实证）

## 三、乱序执行（OoO）核心部件

```
取指 → 译码 → 寄存器重命名(消假依赖WAR/WAW) → 发射到保留站
  → 就绪即乱序执行(多端口ALU/AGU) → 按序ROB提交 → 退休写回
store buffer 攒写；内存消歧预测放行 load
```

- 重命名把架构寄存器映射到物理寄存器池——WAW/WAR 自动消失，只剩真 RAW
- 投机窗口(ROB 深度 ~300+) 内跨百条指令找并行；**这就是"代码局部形态决定性能"的硬件根源**
- Spectre/Meltdown 类漏洞正源于投机执行的瞬态可见性——缓解(重命名清刷/fence)带来真实性能税（量级随代际变化，**待确认**）

## 四、存储层次（性能直觉的坐标系)

| 层级 | 时延量级 | 容量感 |
|------|---------|--------|
| L1d | ~1ns (≈4cy) | 32–48KB/核 |
| L2 | ~4ns | 1–2MB/核 |
| L3 | ~15ns | 十几–几十MB 共享 |
| DRAM | ~80–100ns | GB 级 |
| NVMe SSD | ~20–100µs | TB 级 |
| HDD 寻道 | ~5–10ms | — |

- **缓存行 64B** 是最小传输粒度；结构体布局按热点字段聚集（AoS vs SoS 取决于访问模式）
- 替换≈伪LRU；写策略典型 写回+写分配
- **MESI 一致性**：Modified/Exclusive/Shared/Invalid 四态迁移；跨核共享可写变量每次写都要夺所有权 → **伪共享**：无关变量同行互相打脸，`alignas(64)` 隔离（呼应 [[高并发系统设计]] §二）
- 预取器：步长/流式模式硬件自动预取——顺序访问免费加速，指针追逐(链表/树)喂不饱

### TLB 与大页
- 多级页表省空间但四级查表=四次额外访存 → TLB 缓存映射；TLB miss 走 page walker
- 大页(2MB/1GB) 单条目覆盖更大范围 → DB/JVM/DPDK 的标配优化（[[数据库原理与调优]] buffer pool 受益）

## 五、SIMD 与向量化

- 宽度演进：SSE(128b)→AVX2(256b)→AVX-512(512b)；ARM NEON/SVE
- 自动向量化条件苛刻：循环边界可判、无别名依赖（`restrict`）、无提前退出
- 工程含义：手写标量逐字节循环 vs 库内 SIMD 实现（memcpy/regex 引擎/JSON parser）常差一个数量级——**先怀疑自己没用对向量化库**
- 校验和/字符分类/UTF 校验等热点用 `simdjson` 式手法：一次加载 64 字节位技巧批量判别

## 六、IO 与中断路径

- 中断上下半：top-half 快速应答，bottom-half(softirq/NAPI 轮询) 干重活——高 pps 网络的 NAPI 即"中断转轮询"
- **DMA**：设备直写内存绕过 CPU；NVMe 多队列按核配对消灭跨核乒乓（对照 [[操作系统八股]] io_uring）
- zero-copy 全家桶(sendfile/splice) 的硬件前提就是 DMA 描述符重映射

## 七、性能方法论（把硬件变成度量语言）

1. **Amdahl**：加速比受串行份额封顶；**Gustafson**：扩规模看吞吐视角
2. **Roofline**：算术强度(FLOPs/Byte) 决定吃计算墙还是带宽墙——优化方向二选一不再靠猜
3. **Top-down Microanalysis**(TMA)：把流水线槽位归因到 退役/错误投机/前端受限/后端受限 四象限，perf 工具直接输出
4. 本库锚点：LogNet PoC 用 Python 解析——每行的解释器分发+对象分配远贵于 C 的 SIMD 扫描，这是 M1 规划 native 符号化工具链(addr2line/llvm-symbolizer，见 [[lognet-rootcause-multiagent-architecture]]) 的硬件级理由；FTS 查询 P95 尾部（[[数据库原理与调优]] §七）对应冷页缺页+checkpoint 合并的存储层次效应

## 八、待确认项

> ① 各代 Intel/AMD TMA 分类比例阈值口径；② AVX-512 降频策略在新微架构的放宽程度；③ ARM64 TME 内存加密生态成熟度；④ CXL 内存池化对层级时延表的改写进度。
