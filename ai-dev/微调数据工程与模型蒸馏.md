# 微调数据工程与模型蒸馏

本文覆盖"微调前"与"微调后"两条关键工程线：微调数据工程（预训练/SFT/偏好三大类数据集的格式与 self-instruct 生成法）与模型蒸馏（让大模型当老师、小模型当学生的降本路线），并给出 DeepSeek API 批量造数与蒸馏数据过滤两个可直接运行的脚本。

> [!abstract] 定位与目标
> 本文服务《第 35 章 微调数据工程》《第 31 章 模型蒸馏》与《第 30 章 选型部分》课程骨架。核心问题链：微调数据为什么"质量 > 数量"（Garbage in, garbage out）→ 三大类数据集与 Alpaca/ShareGPT/偏好三种格式 → self-instruct 数据生成 → COT 思维链数据集（R1 风格 <think> 标签）→ 蒸馏与微调的本质区别 → DeepSeek-R1 黑箱蒸馏 800K 数据方案 → Llama-Factory 全量微调实操要点 → GSM8K pass@1 效果评估。读完可获得：① 三类数据集的 JSONL 样例模板；② DeepSeek API 批量造数脚本；③ 蒸馏数据过滤脚本；④ 蒸馏全流程与资源评估清单。

## 核心概念

### 数据是微调的第一性原理

微调（Fine-tuning）本质是用新数据调整模型参数，**数据决定模型行为的上限，训练只决定逼近上限的程度**——"Garbage in, garbage out（垃圾进，垃圾出）"。LIMA 论文（Zhou et al., 2023）给出过硬的证据：仅用 **1000 条精心挑选的指令数据**微调 LLaMA-65B，对话质量反超用 52K 条机器生成数据微调的 Alpaca。结论是：**质量 > 数量**，宁可慢造 1 万条干净数据，不要快收 100 万条噪声数据。

### 三大类数据集对比

| 数据集类型 | 用途 | 数据格式 | 代表数据集 |
|-----------|------|---------|-----------|
| 预训练数据集 | 学语言与世界知识 | 纯文本 | RedPajama、FineWeb |
| SFT 指令数据集 | 学会遵循指令 | instruction/input/output 或多轮对话 | Alpaca 52K、ShareGPT |
| 偏好数据集 | 学会"好坏"排序 | chosen/rejected 对 | HH-RLHF、UltraFeedback |

三者对应训练管线的前后位置：预训练数据喂基座 → SFT 数据教格式与任务 → 偏好数据教偏好（进入 [[强化学习对齐-RLHF到GRPO]] 的 RM/DPO/GRPO 阶段）。

### 数据格式划分

| 格式 | 结构 | 适用场景 | 特点 |
|------|------|---------|------|
| Alpaca | `{"instruction", "input", "output"}` | 单轮指令微调 | 结构简单、工具兼容性最好 |
| ShareGPT | `{"conversations": [{from, value}, ...]}` | 多轮对话微调 | 保留完整角色历史，chat 模板友好 |
| 偏好 | `{"prompt", "chosen", "rejected"}` | RM/DPO 训练 | 一对好坏回答，语义是"相对排序" |

### 蒸馏 vs 微调的本质区别

| 维度 | 微调（Fine-tuning） | 蒸馏（Distillation） |
|------|--------------------|---------------------|
| 目标 | 改变同一个模型的行为 | 让小模型学会大模型的输出分布/行为 |
| 参与者 | 单个模型 + 标注数据 | 教师模型（Teacher）+ 学生模型（Student） |
| 知识流向 | 数据 → 模型参数 | 教师输出 → 学生参数 |
| 典型产物 | 垂直领域助手模型 | 推理能力强的小模型（如 R1-Distill 系列） |

一句话：**微调是"同一个人补课"，蒸馏是"老师教学生"**——蒸馏必须有教师，学生学的不是原始标签而是教师的行为。

### 术语表

| 术语 | 全称 | 一句话解释 |
|------|------|-----------|
| SFT | Supervised Fine-Tuning（监督微调） | 用指令-回答对微调，对齐技术的第一阶段 |
| CoT | Chain-of-Thought（思维链） | 把中间推理步骤写进数据，教模型"先想再答" |
| Self-Instruct | 自指令 | 用 LLM 自己扩展种子任务池的造数方法 |
| KD | Knowledge Distillation（知识蒸馏） | 学生学教师输出的完整概率分布（soft label） |
| Soft Label | 软标签 | 教师输出的概率向量（带温度），比硬标签多"类间相似性"信息 |
| 黑箱蒸馏 | Black-box Distillation | 只调教师 API 拿文本，学生用这些文本做 SFT |
| 白箱蒸馏 | White-box Distillation | 能拿教师 logits，可加 KL 等分布级损失 |
| pass@1 | 单次通过率 | 每题只生成一次答案的正确率，衡量学生真实可用性 |
| dedup | Deduplication（去重） | 过滤重复/近重复样本，防止数据偏差被放大 |

## 原理剖析

### 1. 三类数据集构建实操：JSONL 样例

**SFT 指令数据集（Alpaca 格式，2 条）**：

```jsonl
{"instruction": "计算 2024 年上证指数全年涨幅。", "input": "给定数据：年初 2974.93 点，年末 3351.76 点。", "output": "涨幅 = (3351.76 - 2974.93) / 2974.93 × 100% ≈ 12.67%。"}
{"instruction": "解释什么是市净率。", "input": "", "output": "市净率（PB）= 每股市价 / 每股净资产，衡量股价相对账面价值的倍数。PB < 1 常被视为低估信号，但需结合行业属性判断。"}
```

**COT 思维链数据集（R1 风格，含 <think> 推理字段，2 条）**：

```jsonl
{"instruction": "某股票连续两天涨停，累计涨幅是多少？请先给出推理过程。", "output": "<think>涨停幅度为 10%。第一天后净值变为 1.1 倍，第二天再乘 1.1，共 1.1 × 1.1 = 1.21 倍，即涨 21%，因为复利计算而非简单相加。</think><answer>累计涨幅为 21%。</answer>"}
{"instruction": "本金 1 万元、年化 4%、按年复利，3 年后本息是多少？", "output": "<think>复利公式为 A = P × (1+r)^n，代入 P=10000、r=0.04、n=3：A = 10000 × 1.04^3 = 10000 × 1.124864 ≈ 11248.64 元。</think><answer>3 年后本息合计约 11248.64 元。</answer>"}
```

**偏好数据集（chosen/rejected 对，2 条）**：

```jsonl
{"prompt": "用一句话解释基金定投。", "chosen": "基金定投是每隔固定周期投入固定金额，用时间摊平买入成本、平滑市场波动风险的投资方式。", "rejected": "定投就是买基金。"}
{"prompt": "理财顾问应如何向客户提示风险？", "chosen": "明确告知产品风险等级与历史最大回撤，结合客户风险测评结果说明可能亏损情形，不承诺保本保收益。", "rejected": "这个产品稳赚不赔，闭眼买就行。"}
```

> [!tip] 数据构造三原则
> ① **与目标分布一致**：生产环境问什么，数据里就造什么；② **错误也要采样**：偏好对的 rejected 必须是"真实会犯的错"，而不是随手编的烂回答；③ **字段即合同**：instruction/output 是下游训练代码的接口，改字段等于改合同，全部工具链要同步改。

### 2. Self-Instruct：让 LLM 自己造数据

Self-Instruct（Wang et al., 2022）把"人工写数据"变成"机器造 + 人工抽检"的流水线：

1. **准备种子**：人工写 100-200 条高质量种子任务（覆盖目标场景）；
2. **LLM 扩展**：每次随机抽 8 条已有任务作 few-shot 示例，让 LLM 生成新任务（含指令、输入、输出）；
3. **自动过滤**：去重（与任务池 ROUGE 相似度）、去低质（指令含糊/输出错误/格式非法）；
4. **人工抽检**：随机抽样人工质检，合格回填任务池；
5. **迭代**：重复 2-4 步，任务池滚雪球式增长（原论文用 175 条种子扩展出 52K 条指令）。

### 3. 工具部署：labeler / llamabooster 类工具

数据工程的"工具层"把上述流水线产品化：**labeler 类标注工具**负责偏好对的人工排序与质检界面（展示 prompt + 两条回答 → 点选更好的一条 → 导出 jsonl）；**llamabooster 类微调流水线工具**负责"数据上传 → 训练 → 部署"的一站式编排。二者解决的是同一件事：让非算法同学也能参与造数，让造数动作可追溯、可复现。

### 4. 蒸馏原理：从 KD 软标签到黑箱蒸馏

知识蒸馏（KD，Hinton et al., 2015）的核心思想是**软标签**：教师模型输出的不是"答案=猫"的硬标签，而是带温度 τ 的完整概率分布（猫 0.8 / 豹 0.15 / 老虎 0.05）。这个分布携带了"猫和豹很像"的类间相似性信息，学生学软标签比学硬标签收敛更快、泛化更好。

LLM 时代演化出**黑箱蒸馏**：教师只暴露 API（拿不到 logits），学生只能学教师**生成的文本**。做法就是把教师的输入输出对当 SFT 数据喂给学生——蒸馏退化成"用教师数据做监督微调"，但保留了 KD 的灵魂：**学生学的是教师的行为分布，而不是原始标注**。

### 5. DeepSeek-R1 蒸馏方案剖析：为什么它火

DeepSeek-R1（arXiv:2501.12948）给出的结论颠覆了"小模型必须自己做 RL"的共识：**蒸馏比小模型自己强化学习更划算**。方案细节：

| 环节 | R1 的做法 |
|------|----------|
| 教师 | DeepSeek-R1（RL 训练出的强推理模型） |
| 数据 | **800K 条 SFT 数据**：600K 推理类（R1 生成的含 CoT 输出）+ 200K 非推理类（写作/问答/翻译等） |
| 学生 | 开源小模型：Qwen2.5-Math-1.5B/7B、Qwen2.5-14B/32B、Llama-3.1-8B、Llama-3.3-70B-Instruct |
| 训练方式 | **纯 SFT，不做 RL**——这就是"黑箱蒸馏"：无 KL 白盒，只需教师数据 |
| 效果 | DeepSeek-R1-Distill-Qwen-32B 达 AIME 2024 72.6%、MATH-500 94.3%、GPQA 62.1%（R1 论文数据），部分指标超过 o1-mini |

要点：① **推理能力可以"传染"**——学生没做过一次 RL，只靠模仿教师的推理文本就能获得强推理能力；② 蒸馏的上限受教师限制，教师越强学生越强；③ 小模型自己做 RL（如 DeepSeek-R1-Zero 路线）计算成本高且上限低于蒸馏，R1 论文明确对比过两条路线。

> [!note] 图解说
> 该图原本用于说明"训练（Training）与推理（Inference）"两个阶段的资源差异，在蒸馏语境下可读作两条流水线：**上半条是教师**——离线阶段（Inference）用大模型批量生成数据，只需前向计算、可分布到多卡并行；**下半条是学生**——训练阶段（Training）小模型消费这些数据做 SFT，需要反向传播与优化器状态，显存需求由学生规模决定。教师生成与学生学习在时间上解耦：教师数据是"成品粮"，学生训练是"吃饭"，两阶段可独立扩缩容。

### 7. 蒸馏流程剖析与 Llama-Factory 全量微调要点

标准蒸馏流程四步：**教师选择 → 数据生成 → 学生全量微调 → 效果对比评估**。

- **教师选择**：教师能力 = 蒸馏上限。开源场景可用 DeepSeek-R1 / Qwen-Max 等强推理模型，或自己 RL 出的领域模型；
- **数据生成**：提示词引导（要求输出推理过程、控制格式）+ 过滤（长度/重复度/格式校验）+ 去重；
- **学生全量微调**：推理能力蒸馏通常**不用 LoRA 而用全量微调（Full Fine-tuning）**，因为学生要重塑深层推理模式，LoRA 低秩约束可能压住上限（规模大时再考虑 LoRA 或 QLoRA，见 [[LoRA参数高效微调实战]]）。

Llama-Factory 全量微调实操要点（配置示例）：

```bash
llamafactory-cli train \
  --stage sft \
  --model_name_or_path Qwen/Qwen2.5-7B \
  --dataset distill_reasoning_data \          # 蒸馏得到的 CoT 数据
  --finetuning_type full \                    # 关键：full 全量微调（非 lora）
  --template qwen \
  --deepspeed examples/deepspeed/ds_z2_config.json \   # DeepSpeed stage2 分片优化器
  --output_dir ./outputs/qwen2.5-7b-distill \
  --per_device_train_batch_size 4 \
  --gradient_accumulation_steps 8 \           # 小显存靠累积步数换大有效批
  --learning_rate 1e-5 \                      # 全量微调 lr 更小（LoRA 常用 1e-4）
  --lr_scheduler_type cosine \
  --num_train_epochs 3 \
  --cutoff_len 4096 \
  --gradient_checkpointing true \             # 用计算换显存
  --bf16 true
```

> [!tip] Llama-Factory 的阶段支持
> Llama-Factory 按 `--stage` 划分训练模式：`pt`（预训练）、`sft`（指令微调）、`rm`（奖励模型训练）、`dpo`/`kto`/`orpo`/`simpo`/`grpo`（偏好与 RL 对齐）。即**奖励模型与 GRPO 也可在 Llama-Factory 内完成**，蒸馏数据工程与本库 [[强化学习对齐-RLHF到GRPO]] 的 RM/GRPO 阶段共用同一套工具链。

## 最小可运行 Demo

### Demo 1：用 DeepSeek API 批量生成 SFT 数据

```python
# pip install openai
import json
import time
from openai import OpenAI

client = OpenAI(
    api_key="[已脱敏]",                   # 换成你的 DeepSeek API Key
    base_url="https://api.deepseek.com",     # DeepSeek 官方 OpenAI 兼容端点
)

# 种子问题列表：人工挑选、覆盖目标场景的"金种子"
SEED_QUESTIONS = [
    "什么是基金定投？",
    "如何计算年化收益率？",
    "市盈率与市净率有什么区别？",
]

# 元提示词：把种子问题变成造数指令（self-instruct 的核心一步）
META_PROMPT = """你是金融领域 SFT 数据生成器。请以 JSON 输出 3 条指令-回答对。
要求:
1. 每条指令围绕种子问题改写为不同角度或场景的变体;
2. 回答准确、简洁、无冗余, 200 字以内;
3. 只输出 JSON 对象, 形如 {"examples": [{"instruction": "...", "output": "..."}]}。
种子问题: {seed}"""

def generate(seed: str) -> list[dict]:
    """调 DeepSeek 生成 3 条变体指令数据。"""
    resp = client.chat.completions.create(
        model="deepseek-chat",                # deepseek-reasoner 可产出带推理过程的数据
        messages=[{"role": "user", "content": META_PROMPT.format(seed=seed)}],
        temperature=0.8,                      # 造数要多样性, 温度偏高
        response_format={"type": "json_object"},
    )
    raw = json.loads(resp.choices[0].message.content)
    return raw["examples"]

with open("sft_data.jsonl", "w", encoding="utf-8") as f:
    for seed in SEED_QUESTIONS:
        try:
            for item in generate(seed):
                f.write(json.dumps(item, ensure_ascii=False) + "\n")
        except Exception as e:                # 单条失败不中断整批
            print(f"seed 失败: {seed} -> {e}")
        time.sleep(1)                         # 简单限流; 生产环境用官方并发与重试策略

print("完成: 数据已写入 sft_data.jsonl")
```

### Demo 2：蒸馏数据过滤脚本（长度 / 去重 / 格式校验）

```python
import json
import hashlib

MIN_LEN, MAX_LEN = 20, 2000               # 输出长度阈值 (字符数)

def clean(text: str) -> str:
    """归一化: 去空白 + 小写, 用于重复检测。"""
    return "".join(text.lower().split())

def is_valid(item: dict, require_think: bool = False) -> bool:
    # 1) 格式校验: 必须有 instruction 和 output 字段
    if "instruction" not in item or "output" not in item:
        return False
    # 2) 长度校验: 过滤过短 (无信息) 与过长 (可能截断) 样本
    out = item["output"]
    if not (MIN_LEN <= len(out) <= MAX_LEN):
        return False
    # 3) CoT 数据校验: 蒸馏推理数据必须含 <think> 与 <answer> 标签
    if require_think and not ("<think>" in out and "<answer>" in out):
        return False
    return True

def dedup_filter(src: str, dst: str, require_think: bool = False):
    seen, kept = set(), 0
    with open(src, encoding="utf-8") as fin, open(dst, "w", encoding="utf-8") as fout:
        for line in fin:
            try:
                item = json.loads(line)
            except json.JSONDecodeError:
                continue                    # 非法 JSON 直接丢弃
            if not is_valid(item, require_think):
                continue
            key = hashlib.md5(clean(item["instruction"] + item["output"]).encode()).hexdigest()
            if key in seen:
                continue                    # 精确重复丢弃 (近重复可用 MinHash)
            seen.add(key)
            kept += 1
            fout.write(json.dumps(item, ensure_ascii=False) + "\n")
    print(f"过滤完成: 保留 {kept} 条")

dedup_filter("sft_data.jsonl", "sft_data_clean.jsonl", require_think=False)
```

## 进阶实践与常见坑

### 资源评估与服务器租赁建议

| 学生规模 | 全量微调显存需求（估算，bf16 + AdamW + 激活） | 租赁建议 |
|---------|---------------------------------------------|---------|
| 1.5B-3B | 24-40GB | 单卡 4090/3090（24GB）可训 1.5B，3B 建议 40GB+ |
| 7B | 60-80GB | 1×A100/H100/H20 80GB，或 2×40GB（需 DeepSpeed stage2） |
| 14B | 120-160GB | 2×80GB 或 4×40GB，DeepSpeed stage2/3 |
| 32B-70B | 300-600GB | 8×A100/H100 80GB，DeepSpeed stage3 + offload |

> [!warning] 待验证
> 上表为经验估算（激活显存随序列长度/批大小浮动大），下单前用 1 个 batch 实测峰值显存再决定租卡方案。租赁要点：① 按小时计费的按需实例先小规模验证，再转长租/竞价实例降本；② 数据量小于 10K 条时先用 LoRA 验证数据质量，全量微调留给"数据已打磨好"的阶段；③ 检查点与数据放独立云盘，防止实例释放丢数据。

### 蒸馏前后效果对比：GSM8K pass@1

评估蒸馏是否成功的标准动作：**同一份测试集、同样的采样参数，对比学生蒸馏前后的 pass@1**。

1. **测试集**：GSM8K（小学数学应用题，1319 道测试题）或领域内自建题库；
2. **生成**：0-shot 或 few-shot CoT（如 8-shot），每题只生成一次（temperature=0），解析最终数值答案；
3. **对比对象**：学生基座（蒸馏前）vs 蒸馏后学生 vs 教师（上限参考）；
4. **判定**：蒸馏后 pass@1 应显著高于学生基座，且最好报告多套题的平均值防单集波动。

### 常见坑清单

| 坑 | 现象 | 对策 |
|----|------|------|
| 数据贪多 | 100 万条脏数据不如 1 万条精数据 | 先小批量（1-5K）训练验证数据质量再扩量 |
| 格式污染 | SFT 数据混入 CoT 标签，或反之 | 数据集按用途分文件管理，训练时严格指定 |
| 教师数据泄漏 | 测试集题目被教师生成过并混入训练集 | 数据生成前从题库剔除测试题，或做 n-gram 去污染 |
| 重复样本放大偏差 | 模板化生成导致大量近重复 | 精确去重 + MinHash 近重复去重 |
| 只留推理不留格式 | CoT 数据被截断/标签丢失 | 过滤脚本校验 <think>/<answer> 完整性 |
| 全量微调 lr 过高 | 1e-4 全量微调灾难性遗忘明显 | lr 降到 1e-5 级，必要时混入通用 SFT 数据防遗忘 |
| 只用 pass@1 下结论 | 单次采样方差大 | 多套测试集 + 多次采样（pass@k）交叉验证 |
| 忽略教师成本 | 教师 API 调用账单失控 | 批量任务计价前先估算 token 总量，控制温度与长度 |
