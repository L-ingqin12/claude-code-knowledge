# 逃生/回滚导航（Escape & Rollback MOC）

> [!abstract] 本页用途
> 「系统出问题，该怎么逃生 / 怎么回滚」的入口导航。覆盖 permafrost 缓存链、cache-relay / DeepSeek-400 / 分类器 / 天枢、Claude Code 版本切换，以及事故复盘沉淀的经验。
> 相关：[[Claude-Ops-KB-Home]] · 脚本实体根目录 `D:\Document\local\knowledge\scripts\claude-ops-deployments\`（`root-scripts/`、`cache-relay/`、`cc-version-switch/` 等，均带 deploy / rollback）。

## 一、一句话：逃生 ≠ 回滚

> [!important] 最核心的一句
> **逃生 = 快速止血**（逐层关闭可疑的层/补丁/开关，系统保持运行，低代价、可随时恢复）；**回滚 = 恢复到已知好状态**（还原快照 / git revert / 切回直连，代价较高，一般逃生用尽才用）。**每次逃生只退一层。**

| | 逃生 Escape | 回滚 Rollback |
|---|---|---|
| 目的 | 先让链路恢复可用 | 回到已知好状态 / 基线 |
| 手法 | 逐层关 feature、写 `.disabled`、`passthrough`、disable hook | `git revert` / `git reset` / 还原快照 / 切直连 |
| 关键词 | L0m/L0a/L0b · E0 · F0 · disable | L1–L4 · R0 · rollback · nuke |
| 是否动配置 | 尽量不动，只拨运行开关 | 会动 settings / env / 文件 |
| 代价 / 可逆 | 低，随时能回来 | 高，可能丢缓存 / 丢优化 |

设计原则（各 doc 反复强调）：逃生与回滚**必须与功能同步设计**；软回滚优先、**禁止硬删除脚本**；每次改动前先 `cp` / commit 快照。

L0 / L1–L4 一句话速记（来自 rollback.sh 用法行）：

| 级别 | 命令 | 动作 |
|---|---|---|
| L0m | `model-off` | 关 model 路由（保留 tools / currentDate） |
| L0a | `tools-off` | 关 tools 重排（保留 currentDate） |
| L0b | `patches-off` | 还原 `.orig` → 全部补丁关（回到原版 permafrost） |
| L1 | （默认） | 方案 C→B：permafrost 绕过 proxy、保留缓存优化 |
| L2 | `full` | B→直连：绕过 permafrost、无缓存优化 |
| L3 | `disable` | 禁用 auto-deploy hook |
| L4 | `nuke` | 完全清零（等价 `claude-rollback.sh`） |

## 八、最容易踩的坑

1. **把「逃生」当「回滚」**：一上来就 `nuke` / `full`，缓存优化全丢；应先逐层 L0m → L0a → L0b → L1 → L2。
2. **级数定义看错文档**：06-13 复盘的「四级 L1–L4」是旧定义；七级（补丁级 L0m/L0a/L0b + 结构级 L1–L4）以 `rollback.sh` 头注释为准。
3. **`.orig` 备份陷阱**：`.orig` 若停在「原版」，恢复操作会把所有补丁清零——补丁成功后要 `cp` 更新 `.orig`。
4. **硬删除脚本**：软回滚域禁 `rm`；一律走 `.disabled` / env 开关，删了丢版本历史、无法一键恢复。
5. **改动前不存快照**：没有回滚门禁就没有回滚；每次部署前先 `cp` 备份 / commit。
6. **逃生通道本身没验证**：部署脚本端口竞态曾让 L1 逃生失败；逃生通道要在部署前就绪并实测。
7. **走错相邻文档**：会话中断 / 任务续接是「恢复」（[[claude-interruption-resilience-guide]] / [[claude-context-continuity-guide]]），不是逃生；在本导航找不到答案。
